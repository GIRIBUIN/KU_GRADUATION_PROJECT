# 기능별 커밋 정리와 가져오기 표시 확인 — 2026-10-31

후속 상태: 아래는 첫 10개 커밋을 정리하던 당시 기록이다. 이후 UI 코드 11개 커밋까지 원격 반영된 상태와 문서·증거 보존 내역은 [커밋 정리](../../커밋%20정리%202026-10-31.md)에 기록한다. 후속 최종 코드의 [247건 테스트 원본](ui-final-tests-20261031.jsonl)과 [검증 요약·소스 해시](ui-final-verification-20261031.json)는 별도 기록이며, 아래 초기 단계별 테스트 수와 합산하지 않는다.

시작점은 `bfbb467`이며 앞선 DB v6 커밋 4개는 유지한다. 작업 폴더를 checkout/reset하지 않고 임시 사본에서 커밋별 소스를 구성·검증했다. 같은 파일에 섞인 설정·목록·홈 변경은 각 단계 내용으로 index에 기록한다. 발표자료·별도 이미지·APK·기기 DB·임시 작업 디렉터리는 커밋 대상에서 제외한다. push는 수행하지 않는다.

## 기기에서 확인한 원인

- 기기의 v7 DB를 메모리로 읽어 원본 11개가 모두 Task에 연결되어 있음을 확인했다. 고아 연결 0개, 미완료 eCampus Task 6개다. 제목·메모·HTML·쿠키·DB 파일 자체는 기록하지 않았다.
- 이전 항목 11개는 이관 시 기본 미지정 소속이 유지되어 신규 과목 목록 생성 경로를 타지 않았다. 과목 목록에서 보이지 않은 이유와 관련된다. 실제 기기의 전체 일정 관리에서는 저장된 Task 제목 6개가 화면에 보이는 것도 확인했다.
- 홈의 ‘전체’는 당시 ‘모든 목록 + 오늘’이었다. 날짜 제한이 없는 전체 일정 관리와 혼동했다. 전체 기간 선택을 추가하고 첫 메뉴 이름은 오늘/이번 주/이번 달/전체로 바꿨다. 특정 날짜는 날짜 이름을 쓴다. 메뉴에서 목록 범위를 바꿔도 사용자가 고른 기간은 유지한다.
- 검토 화면의 가져온 항목에 현재 목록을 표시하고 실제 Task ID로 기존 상세를 연다. 신규 저장 직후의 목록도 다시 읽는다. DB commit 성공 사실은 확인 대화상자 전에 기록해, 직후 종료에서도 변경 여부가 유실되지 않게 했다.

## 기존 eCampus 일정 정리

사용자는 ‘미지정의 미완료 6개만 과목 목록으로 이동, 완료·휴지통은 유지’를 선택했다. 검토 화면의 **미지정 N개 과목별 정리 → 정리**로 실행한다.

- 검토된 Task ID 중 현재도 미완료·eCampus·미지정인 항목만 대상으로 삼는다.
- 기존 신규 가져오기와 같은 과목 ID 기반 목록 생성·연결을 재사용한다. `eCampus 폴더 → 과목 목록`을 준비하고 이후 신규 가져오기도 같은 목록을 재사용한다.
- 사용자가 이미 다른 목록으로 옮긴 항목·완료·휴지통·개인 Task는 건드리지 않는다. 제목·메모·태그·마감·원본 ID는 보존한다.
- 그룹·목록 생성과 여러 Task 이동은 같은 transaction이다. 뒤 항목 실패 시 앞 이동·과목 매핑·생성 목록 모두 rollback한다. 재실행은 중복 생성하지 않는다.
- 선택한 Task가 미리보기 뒤 다른 목록으로 바뀌거나 완료/삭제되면 현재 상태를 다시 확인해 이동하지 않는다. OS 알림은 마감/상태를 바꾸지 않는 이 분류 작업에서 재예약하지 않는다.

기기의 실제 6개를 자동 SQL로 이동하거나 기기 DB를 덮어쓰지 않았다. 새 APK를 설치한 후 가져오기 검토에서 사용자가 정리 버튼을 눌러 적용하는 경로다. 현재 버전의 설치·실행 여부는 최종 요약을 따른다.
