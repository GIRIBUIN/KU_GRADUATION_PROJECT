# Flutter 데이터 처리 구현 기준

현재 기준: 2026-11-15 / DB v7. 여기서 백엔드는 별도 서버가 아니라 로컬 저장소·가져오기 처리 레이어를 말한다.

- DB 정의: [app_database.dart](../../lib/data/local/app_database.dart). 실제 관계는 [데이터 모델](../데이터%20모델.md)을 따른다.
- Repository: Task·목록·태그·서브 작업·알림·설정의 조회/저장 진입점. Drift가 현재 구현이다.
- Service: HTTP·파싱·비교·선택 batch 반영·위젯 snapshot 생성 등을 담당한다.
- UI: MainShellScreen이 저장소/서비스와 콜백을 연결하고 StatefulWidget/FutureBuilder로 표시한다. Provider/Riverpod은 현재 의존성이 아니다.
- UI 날짜/색상/펼침 상태는 공통 행과 helper에서 만든다. 폴더에 Task를 직접 저장하지 않는다.

## 보존할 계약

preview는 읽기 전용이다. 현재 Drift 선택 반영은 하나의 transaction이며 OS 알림 API는 commit 후에 실행한다.
원본과 사용자 필드를 분리하고, CHANGED 선택에서 사용자 메모·태그·목록·우선순위를 보존한다.
MISSING은 사용자 선택이며 불완전 응답을 자동 완료/삭제로 해석하지 않는다.

Task DTO의 Folder/folderIds/status 이름을 그대로 물리 스키마라고 해석하지 않는다.
원본 제외는 EcampusItems의 ignored, 완료/휴지통은 Tasks의 시각, 미지정은 필수 기본 목록이다.
서브 작업은 기존 SubTaskRepository로 저장하고 부모 상태를 자동 전환하지 않는다.

기기 간 동기화·계정/서버·충돌 정책은 미구현이다. deleted_entities나 문자열 ID만으로 구현 완료라 하지 않는다.
DB 변경은 이관·데이터 보존·회귀 검증이 필요한 별도 작업이며 UI 개선을 이유로 함께 변경하지 않는다.
