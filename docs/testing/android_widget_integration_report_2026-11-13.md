1. 최종 구현 기능

- 오늘/이번 주에 해당하는 전체 일정 조회. 완료와 미완료 모두 유지하며 보관·삭제 상태는 제외한다.
- 오늘 3개, 주간 5개씩 표시. 인스턴스별 페이지 저장, 이전/다음 이동, 범위 초과 페이지 보정, 빈 목록 0/0 표시.
- 미완료 우선 → 마감 시각 → 사용자 정렬 순서 → 생성 시각 → ID 순으로 정렬.
- 체크 시 DB와 양쪽 JSON 캐시 변경, 완료/해제 재시도 큐 기록, 두 Provider의 설치된 모든 인스턴스 갱신 요청.
- 두 위젯의 등록 버튼은 동일한 빠른 일정 등록 팝업을 사용한다. 실제 UI 버튼은 `+`이다. 요청의 `-`는 기존 등록 버튼을 지칭하는 것으로 해석했으며 버튼 모양은 변경하지 않았다.
- 팝업은 일정과 선택된 새 태그를 하나의 DB 트랜잭션으로 저장하고 두 위젯 갱신 후 종료한다.
- 위 목록은 구현 및 자동 테스트 범위의 확인 결과이다. 실제 런처에서 전체 기능을 검증했다는 의미는 아니다.

수정한 오류와 호환성:

- 두 일정 ID가 같은 Java 해시를 가지면 체크 PendingIntent가 서로 덮어써질 수 있었다. 위젯 종류와 전체 일정 ID를 담은 URI를 추가했다. `Aa`/`BB` 충돌 회귀 테스트를 추가했다.
- Flutter 재시도 경로로 완료 해제하면 completedAt이 남았다. 실제 Drift DB 통합 테스트에서 실패를 재현했고, active로 변경할 때만 완료 시각을 비우도록 수정했다. 완료 시각 기록과 삭제/보관 전환의 기존 정책은 유지한다. 공통 저장소 변경이므로 일반 앱의 완료 해제에도 같은 수정이 적용된다.
- Android 캐시 정렬에는 마감 시각 이후의 비교 기준이 빠져 있었다. 같은 시각의 일정을 완료했다가 해제하면 기존 순서와 달라질 수 있어 Flutter와 비교 기준을 통일했다. 스냅샷에 sortOrder/createdTimestamp를 추가했으며 이전 JSON은 기본값 0으로 읽는다. 이전 캐시에는 정확한 보조 정렬 정보가 없으므로 전체 refresh 후에 완전한 기준이 적용된다.
- DB 스키마, 페이지 크기, 저장 정책, 등록 UI는 변경하지 않았다.

3. 주요 이벤트 처리 흐름

- 전체 갱신: pending 해제/완료 요청을 Repository에 반영 → DB 경로 저장 → 오늘/주간 전체 목록 생성 → 두 JSON 저장 → 두 Provider 업데이트 → 각 인스턴스의 페이지 보정 및 렌더링.
- 페이지 이동: 인스턴스/목표 페이지가 포함된 Broadcast PendingIntent → Provider 및 위젯 ID 검증 → 해당 인스턴스 페이지 저장 → 3개/5개 구간과 체크 Intent 재바인딩.
- 체크: 일정 ID와 종류가 포함된 Activity PendingIntent → WidgetTaskCompleteActivity → WidgetTaskCompleter → 출발 캐시 토글 및 다른 캐시 동기화 → SQLite 상태/시간 변경 → 상반되는 재시도 요청 제거 및 현재 요청 기록 → 두 Provider 갱신.
- DB 접근 실패: 캐시와 재시도 요청을 유지 → 이후 Flutter refresh에서 실제 Repository로 재반영.
- 등록: 공통 WidgetTaskCreateActivity → 전용 Flutter 진입점 → 제목/날짜/태그 입력 → 트랜잭션 저장 → saved 신호 → 두 위젯 refresh → 팝업 close. 저장 후 refresh가 실패하면 이미 저장된 일정을 중복 등록하지 않고 종료한다.

6. 남은 버그 및 개선 사항

- 날짜 경계 자동 갱신 한계: Android Provider는 저장된 JSON만 다시 읽는다. 주기적 APPWIDGET_UPDATE만으로는 Flutter의 오늘/이번 주 DB 조회가 다시 실행되지 않는다. 날짜·주간 범위 계산 테스트는 통과했으나 앱이 장시간 열리지 않으면 지난 날짜 목록이 남을 수 있다. 자정/시간대 변경 및 부팅 시 백그라운드 DB 재조회 경로가 필요하다. 이번 수정에는 별도 백그라운드 실행 구조를 도입하지 않았다.
- 다크 모드: 위젯 색상과 등록 앱 테마가 현재 라이트 중심이다. 시스템 다크 모드를 따라가는 기능은 구현되어 있지 않으며 다크 모드에서의 가독성도 미검증이다. 색상 정책 변경은 이번 최소 오류 수정에서 제외했다.
- 동시 실행 경쟁: Flutter 전체 refresh와 네이티브 체크가 동시에 실행될 때 캐시/재시도 큐 갱신은 원자적이지 않다. UI 순차 테스트만으로 무손실을 보장할 수 없다. 멀티 엔진·고빈도 조작 스트레스 테스트와 큐 버전/직렬화 검토가 필요하다.
- 네이티브 SQL 변경은 별도 Flutter DB 연결의 Drift 스트림에 직접 통지하지 않는다. 메인 앱 복귀 재조회 흐름과 동시에 열린 등록 팝업의 교차 변경은 실기기에서 확인해야 한다.
- DB 재시도나 팝업 갱신 실패는 즉시 복구를 보장하지 않으며 다음 Flutter refresh에 의존한다.
- resize/다크 모드/재부팅에 대한 검증 부족은 자동 테스트 통과로 해소되지 않는다.

- [ ] 최종 debug APK 설치 후 앱을 한 번 열고 오늘/주간 위젯을 각각 2개 설치한다. 설치 전 데이터를 보존한다.

- [ ] 이번 주 다른 날짜 일정과 다음 주 일정을 추가한다. 오늘은 오늘만, 주간은 이번 주만 표시되는지 확인한다. 이미 지난 오늘 마감 시각도 포함되어야 한다.

- [ ] 2페이지로 이동하자마자 체크한다. 보였던 일정 ID만 DB에서 완료되고 다른 일정이 잘못 변경되지 않아야 한다.
- [ ] 오늘과 주간에서 같은 일정을 번갈아 완료/해제한다. 양쪽 모든 인스턴스의 체크, 취소선, 진행률, 미완료 우선 순서가 갱신되어야 한다.
