# KUTODO 데이터 모델

기준: 2026-11-15 / [app_database.dart](../lib/data/local/app_database.dart)의 **schemaVersion 7**.
[관계도](diagrams/db-v7.md)와 [변환용 DBML](database.dbml)은 같은 활성 저장 구조를 설명한다.

## 관계와 저장 테이블

```text
folder_groups(폴더) ← task_lists(목록) ← tasks(할 일)
tasks ← task_tags → tags(전역 태그)
tasks ← sub_tasks(서브 작업)
ecampus_courses → 기본 목록
ecampus_items → 선택적으로 tasks에 연결
```

| 테이블 | 실제 역할 |
| --- | --- |
| `tasks` | 사용자 제목·마감·메모·우선순위·정렬·필수 `list_id`·완료/삭제 시각 |
| `task_lists` | 목록 이름·색상·정렬. 선택적인 `folder_id`로 폴더에 소속 |
| `folder_groups` | 목록을 묶는 상위 폴더. 할 일이 직접 참조하지 않음 |
| `tags`, `task_tags` | 전역 태그와 할 일의 복수 연결 |
| `sub_tasks` | `task_id`로 부모 연결, 제목·position·완료/삭제 시각 |
| `ecampus_courses` | source scope 안의 강의 식별값·이름·기본 배치 `list_id`. 선택적 `tag_id`는 남아 있는 저장 호환 필드 |
| `ecampus_items` | 원본 식별값·제목·마감·과목·유형·관측 시각·import_state·선택적 task_id |
| `import_sessions` | 반영 성공 때 저장하는 가져오기 기록. 로그인 세션이나 실패/취소 전체 이력 저장소가 아님 |
| `task_reminders` | 할 일별 enabled·offset_minutes 규칙 |
| `local_notification_schedules` | 해당 기기의 OS 알림 ID·예약 시각·오류 |
| `app_settings` | 표시·정렬·기간·숨김·스와이프·알림 기본값 등의 key/value |
| `migration_issues` | 이관에서 발견한 예외 데이터와 이유 |
| `deleted_entities` | 영구 삭제 식별 기록. 이것만으로 기기 간 동기화가 구현된 것은 아님 |

## 상태와 원본 분리

`tasks`에는 물리 `origin`·`status`·eCampus 원본 컬럼이 없다.
Mapper가 `deleted_at` → deleted, `completed_at` → completed, 나머지 → active로 변환한다.
연결된 원본이 있으면 DTO의 origin이 ecampus가 된다.

`ecampus_items.import_state`는 imported / ignored / unreviewed다.
imported는 Task 연결이 필수이고, ignored/unreviewed는 연결이 없어야 한다.
제외는 별도 Task 상태 행을 만드는 대신 ignored 원본으로 보관한다.
UI에서 보이는 `TaskStatus.excluded`는 이 원본을 변환한 호환 표현이다.

원본의 `(source_scope_id, external_key)`와 Task 연결의 고유 제약으로 동일 원본 중복을 막는다.
현재 scope는 `legacy-local`이며 확인된 LMS 계정 ID나 클라우드 사용자 ID가 아니다.
`ImportSessions.appliedCount`는 반영 서비스가 반환한 결과 수이며 신규 생성 수만을 뜻하지 않는다.

## 목록·태그·서브 작업

- 모든 Task는 목록 하나에 속한다. `kutodo:inbox`는 **미지정**이며 폴더에 넣거나 삭제할 수 없다.
- 완료·삭제·복원해도 목록 정보는 유지한다. 재가져오기가 사용자의 목록 이동을 되돌리지 않는다.
- 태그는 소속 목록과 독립적이다. 과목 목록의 이름·색상과 태그를 같은 것으로 해석하지 않는다.
- 서브 작업은 `SubTasks`의 별도 행이다. DTO `parentTaskId`로 Task끼리 연결하는 기능이 아니다.
- 서브 작업의 `isDone`은 저장된 완료 시각을 변환한 값이며, 부모 자동 완료는 하지 않는다.

## 코드 호환 이름

| 코드 이름 | 실제 의미 |
| --- | --- |
| `Folder`, `FolderRepository`, Drift `Folders` | 목록 / `task_lists` |
| `FolderGroup` | 상위 폴더 / `folder_groups` |
| `Task.folderIds` | 화면 호환 필드. 실제 저장은 단일 목록이며 `Task.listId` 사용 |
| Drift `Tasks.folderId` | 실제 컬럼명은 `tasks.list_id` |
| `NotificationSetting.daysBeforeDue` | 이름과 달리 **분 단위** offset |
| `Task.isArchived` | 완료·삭제·제외를 묶는 코드 판정. 목록 보관 메뉴를 뜻하지 않음 |

새 일반 Task ID는 UUID를 사용하지만 위젯의 기존 personalTaskDraft는 시각 기반 ID를 생성한다.
이관은 기존 ID를 보존한다. 모든 생성 경로가 UUID로 통일됐다고 주장하지 않는다.
날짜는 Drift DateTimeColumn의 Unix 초 저장을 사용하며 화면에서 현지 날짜/시간으로 표시한다.

v5/v6 이관의 원본 보관용 `legacy_*` 테이블은 업그레이드한 DB에만 남을 수 있다.
활성 테이블과 구분하며 상세 이식 결정·당시 측정은 [v6 적용 기록](specifications/DB%20재설계%20비교와%20적용안.md)을 본다.
