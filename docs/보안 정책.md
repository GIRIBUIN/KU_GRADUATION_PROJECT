# KUTODO 보안·eCampus 세션 정책

현재 Flutter 구현 기준: 2026-11-15. 과거 연구계획서와 인증 실험의 장기 로그인 구상을 현재 기능으로 설명하지 않는다.

## 인증과 세션 수명

사용자가 앱의 WebView에서 직접 로그인한다. 앱 설정·DB에 eCampus 아이디/비밀번호를 저장하지 않는다.
WebView 쿠키에서 얻은 EcampusSession은 이번 가져오기의 HTTP 요청에 사용한다.
현재 암호화된 장기 세션 저장·자동 로그인 복원 기능은 없다.

```text
기존 쿠키 정리 → 사용자 로그인 → 조회·비교 → 사용자 검토·반영
→ 서버 로그아웃 시도 → 앱의 세션 참조 제거·WebView eCampus 쿠키 정리
```

[가져오기 화면](../lib/presentation/screens/sync/ecampus_sync_progress_screen.dart)의 `_finishSession`을
정상 반영·종료·실패·취소·dispose에서 재사용한다. 다음 가져오기는 다시 로그인한다.
[서버 로그아웃](../lib/data/services/http_ecampus_auth_service.dart)의 `finally`에서도 로컬 쿠키 정리를 호출한다.
대상은 앱 WebView의 eCampus URL 쿠키이며 시스템 브라우저나 학교 공식 앱 전체를 로그아웃시키는 기능은 아니다.
플랫폼 쿠키 API 자체가 실패한 경우까지 삭제 완료를 보장하지 않으며 오류 안내 후 다음 실행에서 다시 정리한다.

## 수집과 저장

- eCampus 체크리스트를 읽고 로컬 사용자 작업으로 가져온다. 학교 원본의 제출·수정·삭제는 하지 않는다.
- 사용자 할 일·원본 snapshot은 앱 내부 Drift/SQLite에 저장한다. 현재 별도 계정 서버나 기기 간 동기화 서버는 없다.
- DB v7의 원본/Task 분리와 외래키는 데이터 무결성을 위한 것이며 저장 암호화·계정 분리 구현을 뜻하지 않는다.
- 계정·쿠키·세션 값·원본 HTML 전체·기기 DB 사본은 공개 로그나 포트폴리오 증거에 넣지 않는다.
- 재현은 합성 fixture를 우선 사용하고 기기 확인은 필요한 연결·상태 건수와 해시를 남긴다.

## 가져오기 오류

preview는 읽기 전용이고 반영 batch는 현재 Drift transaction을 사용한다.
실패한 저장은 rollback되며 OS 알림 변경은 commit 후에만 실행한다.
불완전한 조회는 누락 판정에서 제외한다. 기본 MISSING 선택은 유지다.
알림 후처리 오류와 쿠키 정리 오류는 이미 성공한 Task 저장을 되돌리는 근거로 사용하지 않는다.

## 외부 연동·배포 범위

[2학기 미팅 자료](materials/KUTODO_2026_2학기_미팅.pptx)의 12쪽에는
당시 문의 결과로 공개 API·일반 외부 연동 미제공, 대학 담당 부서 경유 필요, 학교 허용 범위 미확인이 기록돼 있다.
이는 현재의 배포 승인이나 장기 로그인/주기 조회 허용을 증명하는 자료가 아니다.

현재 개발은 사용자 요청 기반 WebView 가져오기를 기준으로 검증한다.
OCR·공식 API 연동·주기적 조회·기기 간 동기화는 별도 검토 과제다.
배포·사용자 평가를 진행하기 전 실제 허용 범위와 수집/보관 범위를 확인한다.
