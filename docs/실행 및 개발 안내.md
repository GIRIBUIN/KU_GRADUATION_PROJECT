# KUTODO 실행 및 개발 안내

기준일: 2026-11-15. 개발 브랜치는 main 하나이며 현재 DB schemaVersion은 7이다.
검증 기록의 환경은 Flutter 3.44.7 / Dart 3.12.2, Windows / Android Galaxy S24다.
프로젝트의 Dart SDK 제약과 실제 패키지는 [pubspec.yaml](../pubspec.yaml), [pubspec.lock](../pubspec.lock)을 확인한다.

## Android 실행·설치

Flutter와 Android SDK를 준비하고 USB 디버깅을 허용한 기기를 연결한다.

```powershell
flutter pub get
flutter devices
flutter run -d <device-id>

# APK를 직접 설치할 때
flutter build apk --debug --no-pub
adb -s <device-id> install -r build/app/outputs/flutter-apk/app-debug.apk
```

`install -r`은 기존 패키지의 업데이트 설치다. 데이터를 보존해야 할 때 uninstall/앱 데이터 지우기를 먼저 실행하지 않는다.
설치·앱 실행 성공은 실제 계정 가져오기·런처 위젯·알림 전체 동작을 검증했다는 뜻이 아니다.

## 개발 중 검증

```powershell
flutter analyze --no-pub
flutter test --no-pub --concurrency=1 test/data test/presentation
```

변경 범위에 맞는 테스트를 먼저 선택한다. `test/benchmarks`는 수동 측정용이며 일반 회귀 테스트와 구분한다.
실제 eCampus 계정·학교 서버·런처 위젯·정확 알림/절전 조건은 [수동 시나리오](테스트%20시나리오.md)를 따른다.

Android 네이티브 위젯 변경 시 Android Studio의 JDK와 SDK가 필요하다.
Windows의 기본 설치 경로를 사용한다면:

```powershell
cd android
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
.\gradlew.bat :app:testDebugUnitTest --tests 'com.example.ku_task_management.WidgetIntegrationTest' --tests 'com.example.ku_task_management.WidgetDateRefreshTest' --tests 'com.example.ku_task_management.WidgetPageTest'
```

이 검사는 Robolectric 테스트이며 실제 런처 결과와 구분한다.
오늘/이번 주 위젯은 Android 런처의 위젯 추가 메뉴에서 등록한다. 별도 위젯 설정 페이지는 없다.
